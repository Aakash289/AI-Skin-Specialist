# AI Skin Specialist

AI Skin Specialist is a Gradio-based consultation assistant. A patient records a spoken description of their skin concern and uploads either a photo or a short video of the affected area. The app transcribes the patient's voice, sends the description together with the image (or video frames) to Claude, and returns both a written and a spoken doctor-style response.

This version uses Claude as the core reasoning and vision model, with support for either an image or a video as visual input, and dependency management handled through uv.

Important: this project provides general informational guidance only. It is not a medical diagnosis and should not replace care from a licensed dermatologist or clinician.

## What this app actually does

- Groq Whisper transcribes the patient's recorded voice into text.
- Claude (Anthropic) reads the transcribed text plus the uploaded image, or a set of frames extracted from the uploaded video, and generates a short, doctor-style spoken response.
- Deepgram converts that text response into an audio file that plays back automatically in the browser.
- Gradio ties all of this together into a single web page: record voice, upload image or video, click Analyze, get a transcript, a written response, and a spoken response.

This app does not require an image specifically. A user can submit either an image or a video, and the app picks whichever one was provided. Claude has no native video understanding, so when a video is submitted, the app extracts several evenly spaced frames from it using OpenCV and sends those frames to Claude as a set of images instead. From the user's perspective, video "just works", even though under the hood it is being converted to frames first.

## Tools and services used

**Gradio** renders the web interface: the input card (voice, image, video, submit button) and the output card (transcript, written response, audio player). Custom CSS is used throughout `main.py` to give the interface its own visual identity instead of Gradio's default theme.

**Anthropic (Claude)** is the model that actually reasons about the patient's description and their skin photo or video frames, and writes the short doctor-style reply.

**Groq (Whisper)** is used only for speech-to-text: converting the patient's recorded microphone audio into a text transcript. Groq's Whisper endpoint is fast and inexpensive for transcription specifically.

**Deepgram** handles text-to-speech: turning the doctor's written response into a spoken MP3 so the user hears a reply rather than only reading one.

**OpenCV (`opencv-python`)** is used to open uploaded video files and extract a handful of representative frames, which are then sent to Claude as images. This is what makes video input work despite Claude not accepting video files directly.

**SpeechRecognition, pydub, and PyAudio/PortAudio** handle capturing microphone audio and converting the raw recording into an MP3 file that can be sent to Groq for transcription.

**python-dotenv** loads API keys and configuration out of a local `.env` file so nothing sensitive is hardcoded into the source.

**uv** manages the Python version, virtual environment, dependencies, and lockfile for the whole project. All commands in this README run through `uv run` or `uv add`/`uv sync` rather than plain `pip` or a manually activated virtualenv.

### `main.py`

This is the entry point and the only file you run directly. It builds the Gradio interface (title bar, patient input card, doctor response card, footer) and defines `process_inputs()`, the function that runs when the user clicks "Analyze Concern". `process_inputs()` validates that both a voice recording and at least one of image/video were provided, then calls the other three modules in sequence: transcribe the voice, send the transcript plus image/video to Claude, convert Claude's reply to audio, and return all three results to be displayed.

### `Brain_of_the_doctor.py`

This is the core reasoning module. It builds an Anthropic client from `CLAUDE_API_KEY`, and exposes `brain_of_the_doctor(patient_text, image_filepath=None, video_filepath=None)`. If a video path is given, it calls `extract_frames()` to pull several evenly spaced frames out of the video with OpenCV, base64-encodes each one, and sends them all to Claude as separate image blocks in a single message. If only an image path is given, it sends that one image instead. Either way, the patient's transcribed text is included as the accompanying prompt, along with instructions telling Claude to respond briefly, in a confident doctor's tone, and with no markdown formatting, since the output is converted to audio afterward.

### `voice_of_the_user.py`

Handles capturing the patient's voice. `record_audio()` listens on the default microphone, adjusts for ambient noise first, records until the patient stops talking or a time limit is hit, and saves the result as an MP3 using pydub. `transcribe_patient_voice()` then sends that MP3 to Groq's Whisper endpoint and returns the transcribed text, forcing English language detection so short or noisy recordings don't get misidentified as another language.

### `voice_of_the_doctor.py`

Handles turning Claude's text response into audio. `convert_text_to_doctor_audio()` sends the text to Deepgram's text-to-speech API and streams the resulting MP3 to disk, saving it as `doctor_response.mp3` by default. `play_audio()` is a standalone helper for playing an audio file directly from the command line on macOS, Windows, or Linux, useful for testing outside of the Gradio interface.

## Requirements


## Setup

Clone or open the project folder, then run:

```
uv sync
```

This reads `pyproject.toml` and `uv.lock`, creates `.venv` if needed, and installs all locked dependencies. If your project doesn't have a `pyproject.toml` yet, add each dependency as you go with `uv add <package>`, which creates one automatically.

## Environment variables

Create a `.env` file in the project root:

```
CLAUDE_API_KEY=your_anthropic_api_key_here
GROQ_API_KEY=your_groq_api_key_here
DEEPGRAM_API_KEY=your_deepgram_api_key_here

```

All three keys are required for the app to run end to end: `CLAUDE_API_KEY` for the doctor's reasoning and vision, `GROQ_API_KEY` for voice transcription, and `DEEPGRAM_API_KEY` for the spoken response. Do not commit `.env` or real API keys to version control.

## Run the app

```
uv run main.py
```

Gradio prints a local URL, usually:

```
http://127.0.0.1:7860
```

Open that URL in your browser.

4. Review the transcript, the doctor's written guidance, and listen to the generated audio response.

## Development notes

- `main.py` imports `brain_of_the_doctor` from `Brain_of_the_doctor.py`, the single implementation of the doctor logic used by the app.
- Claude does not accept video as a native input type. Video support works by extracting frames with OpenCV and sending them as multiple images in a single request, not by sending the raw video file.
- If `video_filepath` is provided, it takes priority over `image_filepath` inside `brain_of_the_doctor()`. If a user somehow submits both, the video is used and the image is ignored.
- Generated doctor audio is written to `doctor_response.mp3` by default.
- Gradio launches with `debug=True` in `main.py`.

## Troubleshooting

**`ModuleNotFoundError` for any package** — the package isn't installed in the project's environment yet. Install it with `uv add <package-name>`, then rerun with `uv run`.

**`ffmpeg` not found** — install it for your OS as described above, then fully close and reopen your terminal so the updated PATH is picked up. Confirm with `ffmpeg -version`.

**`RuntimeError: CLAUDE_API_KEY environment variable is not set`** — confirm a `.env` file exists in the project root (not `.env.txt`), sits next to your Python files, and contains a line exactly like `CLAUDE_API_KEY=sk-ant-...` with no quotes or extra spaces.

**Claude responds about the wrong subject, or an unrelated image** — this is expected behavior, not a bug. The prompt in `Brain_of_the_doctor.py` instructs Claude to only discuss skin concerns; if a non-skin image is submitted, Claude will point that out rather than analyze it as skin.

**`FileNotFoundError` when extracting video frames** — this usually means the video file path is wrong or the file does not exist, not that OpenCV failed to read a valid file. Confirm the path passed to `brain_of_the_doctor()` actually points at an existing `.mp4` file.

**Microphone not detected** — check your OS's microphone permissions, confirm no other app is using the microphone, and confirm PortAudio/PyAudio installed correctly for your platform.

**Deepgram or Groq errors** — confirm the relevant API key is valid and that the model name set in `.env` (`DEEPGRAM_TTS_MODEL` or `WHISPER_MODEL`) is actually available for your account.

## Security

- Keep `.env` private and out of version control.
- Treat any patient images, videos, and audio files as sensitive data.
- This repository may include sample media files for local testing; production use should define a clear data retention and privacy policy before handling real patient data.
